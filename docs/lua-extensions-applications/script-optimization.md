# Lua脚本的优化

脚本写得省一点，应用程序的性能和响应速度都能上来。下面这些技巧按环节分开讲。

## 1. 优化数据结构

Lua 的表是最通用的数据结构，数组、字典都能当，需要高效查找的数据就用字典特性。另外别把表嵌套得太深：层级一多，访问和处理的复杂性都跟着涨，结构能简则简。

## 2. 减少函数调用开销

函数调用本身有开销，递归和过于频繁的调用能省则省。小而频繁调用的函数，可以把代码直接嵌进调用处（内联），把这一步的开销去掉。

## 3. 提高脚本执行效率

脚本可以预编译成字节码，省掉运行时的解析开销，用`luac`工具：
  ```bash
  luac -o script.luac script.lua
  ```

全局变量比局部变量慢，变量尽量局部化，在函数内部使用。

## 4. 优化循环结构

循环次数先砍到需要的最少，循环体里的复杂计算能挪出去就挪出去。循环中访问表长度时，先把长度缓存到局部变量，别每次重算：
  ```lua
  local len = #array
  for i = 1, len do
      -- 操作 array[i]
  end
  ```

## 5. 使用有效的字符串操作

频繁连接字符串会产生大量中间字符串，多个字符串的拼接交给`table.concat`：
  ```lua
  local t = {"Hello", " ", "world"}
  local result = table.concat(t)
  ```

如果已知字符串的最终长度，也可以预先分配缓冲区，减少动态分配的次数。

## 6. 内存管理

垃圾回收的设置按实际需要调，`collectgarbage`函数可以手动控制：
  ```lua
  collectgarbage("setpause", 100)  -- 设置垃圾回收的暂停阈值
  collectgarbage("setstepmul", 500)  -- 设置垃圾回收的步长倍率
  ```

对象创建能省则省，尽量重用，对象池这类技术可以管住对象的生命周期。

## 7. 编写高效的算法

按具体问题选算法和数据结构，复杂度太高的避开。性能关键的部分值得专门优化，把时间复杂度和空间复杂度都往下压。

## 8. 调试和分析

性能瓶颈靠工具找，Lua 的性能分析工具（如`luaprofiler`）能派上用场。开发和测试阶段用日志记下关键操作的性能数据，问题好定位，代码也好优化。

## 9. LuaJIT优化

如果使用LuaJIT（Lua的Just-In-Time编译器），还能再快一截。通过它的 Foreign Function Interface (FFI) 库可以直接调用C函数；JIT 编译是自动进行的，只要确保跑在支持JIT的环境中。
